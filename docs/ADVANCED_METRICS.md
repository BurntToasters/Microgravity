# Advanced metrics collection

Advanced sampling is optional and runs through the authenticated helper. The app requests fixed `nettop` and `powermetrics` commands, never arbitrary arguments. Sampling is asynchronous, has at most one request set in flight, and is scheduled no more often than every five seconds. Cached readings keep the helper capture time; samples older than 30 seconds are unavailable. Helper absence, denial, command failure, invalid output and stale data are not zeros.

`nettop -n -P -x -L 1 -J bytes_in,bytes_out` requests raw per-process CSV totals. `man nettop` documents `-P`, `-x`, `-L`, and column selection. The observed raw layout has an unlabeled first process column followed by `bytes_in` and `bytes_out`, with an optional trailing empty CSV field; the parser also accepts labeled `interface` layouts with other columns such as time or state. Input is limited to 4 MiB. The parser handles quoted CSV names and rejects malformed schemas, malformed quoting, and ambiguous duplicate PIDs. BSD PID/start-time identities are independently enumerated before and after the command; a missing or changed identity is discarded. Rates use monotonic counter differences, with warm-up, counter reset, and long gaps represented as unavailable. No socket destinations or command output are persisted.

`powermetrics -f plist -i 1000 -n 1 -s tasks,cpu_power,gpu_power --show-process-gpu` emits NUL-separated plist records according to local `powermetrics --help`. On the observed plist shape `gpu.idle_ratio`, GPU active percentage is `100 * (1 - idle_ratio)`; the parser requires a finite numeric fraction in [0,1]. This key is an observed schema, not a public compatibility guarantee; for an example consumer see [thor's parser](https://github.com/okuvshynov/thor/commit/bcc34324af629813b38d8958b3e2eb828b7f0eb3). Synthetic tests encode this specific shape and do not claim a hardware capture. Unsupported or malformed shapes are unavailable. The parser also accepts only explicitly unit-named hypothetical fields: `processor.cpu_power_mw`, `processor.gpu_power_mw`, and `processor.ane_power_mw` together, converted to estimated component watts, and `tasks[].gpu_time_ms` or `tasks[].gpu_time_ns`, converted to seconds. A task PID must retain the same BSD start identity before and after the power sample. Generic `gpu_time`, partial power components, unknown units, duplicate task PIDs, and malformed values are unavailable. These synthetic field shapes have not been observed in real Apple output, so availability on any hardware is unverified; they are not claims about actual powermetrics schemas.

Live helper installation, authorization, process attribution and field units on Intel and Apple silicon still require signed, target-host testing. The privileged commands were not run as root for this implementation.
